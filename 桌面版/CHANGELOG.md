## V3.1.2（2026-10-25）— 全量代码审查修复 + 任务看板升级 + 中国隐私合规 + 一键部署

### 代码审查修复（通读前端 + Rust + 配置后发现）
1. **草稿重启后丢失（重要）**：咨询记录/方案/随手记的自动保存草稿写在数据库 preferences 表里，但登录时只预加载了 2 个偏好键，草稿从未被读回——重启程序后「已恢复自动保存的草稿」永远不会出现。已新增 Rust 命令 `db_list_prefs`，登录时全量加载偏好，草稿可跨重启恢复（冒烟测试含重启模拟并通过）。
2. **手动备份后仍被反复提醒备份**：`desktopBackup()` 成功后没有更新 `lastBackup`，备份提醒永远不消失。已修复。
3. **「从前次咨询记录复制」会复制同一天的记录**：与产品规格（严格早于当前日期）不符，已改为 `<` 当前日期。
4. **数据写入防清空护栏**：Rust `db_set_state` 现在拒绝缺少核心集合（clients/sessions/events）的载荷，避免前端异常时把整个工作区误清空。
5. **全局搜索漏了日程**：已补齐（来访者/记录/随手记/目标/任务/收费/模板/转介/日程全覆盖）。
6. **收费状态与金额不一致**：保存收费时按实收/应收自动校正为 已收款/部分收款。
7. 其他：手动备份文件名加毫秒防同秒覆盖；每日自动备份改按北京时间计算日期；新建用户/首个管理员显示名为空时回退为用户名；锁定后 `storage()` 的未处理异常已消除；Tauri 权限文件移到规范位置 `src-tauri/capabilities/default.json`（原放在包根目录可能不被加载）。

### 修复的重大缺陷
1. **toast 失效（原版即存在）**：`id="toast"` 的元素经全局 id 绑定覆盖了 `toast()` 函数，22 处保存成功提示调用都会抛 TypeError。已将元素改名为 `toastBox`，并加固 id 绑定（不再覆盖已有函数）。
2. **今日工作台「今日」渲染必失败（原版即存在）**：`renderToday()` 写入不存在的 `#todayEvents` 容器，每次渲染都会报错且该区块从不显示。已在今日工作台补上「今日日程」卡片与容器。
3. **保存状态永远停在「正在保存…」**：bridge 的 `queueWrite` 返回 `true` 而非 Promise，`save()` 的成功/失败回调从未触发。现在写入队列返回真实 Promise，并建立唯一持久化入口 `persistWorkspace()`：内存状态 → SQLCipher 提交确认 → 更新状态；失败时明确弹窗且不显示「已保存」。
4. **Windows 发行版弹出黑色控制台窗口**：`main.rs` 补上 `#![cfg_attr(not(debug_assertions), windows_subsystem = "windows")]`。
5. **文案与实现不一致（数据位置/自动备份）**：界面原声称数据「位于程序同目录」、且「每天首次启动和正常退出时自动备份并保留 30 份」，但 Rust 实际使用系统应用数据目录且从不自动备份。现已实现真实的每日自动备份（每次成功登录后，当天首次登录时生成一份经完整性校验的加密数据库备份，仅保留最近 30 份自动备份），界面文案同步改为真实描述，并显示实际数据库路径；便携模式（程序旁 `portable.mode`）说明保留。
